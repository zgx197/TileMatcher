# 安卓打包脚本说明

## 目标

这份脚本用于固定当前项目的安卓打包链路，避免再次出现“版本号是新的，但 APK 中实际运行的资源和 C# 程序集仍是旧的”问题。

脚本强制使用下面这条正确流程：

1. 同步版本号、包名、方向等构建元数据
2. 调用 Godot `--headless --export-debug` 刷新最新导出资源
3. 对 Godot 导出的 APK 进行签名
4. 使用 `apksigner` 和 `aapt` 做最终校验

核心原则：

- 不再直接拿旧的 `godot/android/build/src/main/assets` 快照跑 Gradle 打包
- 必须先走一次 Godot 正式导出，确保 `.godot/mono/publish`、`project.binary`、`assets.sparsepck` 都被刷新

问题背景详见：

- [安卓打包链路问题记录](./研发记录/安卓打包链路问题记录.md)

## 脚本位置

- [scripts/build-android.ps1](../scripts/build-android.ps1)

## 本地用法

默认情况下，脚本会读取：

- `GODOT_EXE`
- `ANDROID_SDK_ROOT`
- `JAVA_HOME`
- `ANDROID_DEBUG_KEYSTORE`

如果没有设置，也可以显式传参。

示例：

```powershell
.\scripts\build-android.ps1 `
  -GodotExe "D:\GodotCSharp\Godot_v4.6.1-stable_mono_win64\Godot_v4.6.1-stable_mono_win64.exe" `
  -AndroidSdkRoot "C:\Users\Guoxi\AppData\Local\Android\Sdk" `
  -JavaHome "C:\Program Files\ojdkbuild\java-17-openjdk-17.0.3.0.6-1" `
  -KeystorePath "C:\Users\Guoxi\AppData\Roaming\Godot\keystores\debug.keystore" `
  -KeystorePassword "android" `
  -KeyAlias "androiddebugkey" `
  -KeyPassword "android" `
  -PackageName "com.zgx197.tilematcher" `
  -VersionName "0.1.5" `
  -VersionCode 6 `
  -ManifestOrientation "portrait"
```

默认输出目录：

- `godot/build/android/`

默认会生成两个文件：

- `TileMatcher-unsigned.apk`
- `TileMatcher-<版本号>-android-debug.apk`

其中第二个文件是签名后的最终可安装包。

## 脚本会同步哪些文件

脚本会更新以下元数据文件，确保本地显示、导出配置和 Android manifest 保持一致：

- `godot/project.godot`
- `godot/export_presets.cfg`
- `godot/android/build/src/main/AndroidManifest.xml`
- `godot/android/build/src/debug/AndroidManifest.xml`

其中：

- `project.godot` 中的 `tilematcher_build/*` 会被游戏内 DEBUG 面板读取
- `export_presets.cfg` 决定 Godot 导出的默认版本和包名
- 两份 `AndroidManifest.xml` 保证打进包里的声明与脚本参数一致

## 已处理的脚本边界问题

### 1. PowerShell 中文编码问题

脚本最初在控制台环境中因为中文字符串被错误解码，导致 PowerShell 直接解析失败。

当前处理方式：

- 脚本主体改为 ASCII 字符串
- 只在文档中保留中文说明

这样做的原因是：

- 打包脚本的第一优先级是稳定执行
- 不能让控制台编码差异影响本地或 CI 出包

### 2. 配置文件 BOM 问题

脚本曾经使用 `Set-Content -Encoding UTF8` 回写 `project.godot` 和 `export_presets.cfg`，这会在部分 PowerShell 版本下写入 UTF-8 BOM。

而 Godot 对这些配置文件的解析链路对 BOM 不够稳，曾经导致：

- `export_presets.cfg` 虽然文本内容正常
- 但 Godot 提示 `Invalid export preset name: Android`

当前处理方式：

- 脚本统一使用 `UTF8Encoding($false)` 写回文件
- 明确保证配置文件为 UTF-8 无 BOM

### 3. Godot 导出返回码问题

在某些场景下，Godot headless export 虽然成功生成了 APK，但进程退出码并不一定是 `0`。

当前处理方式：

- 先检查 `TileMatcher-unsigned.apk` 是否真实生成
- 若 APK 已存在，则继续进入签名与校验步骤
- 仅将 `apksigner` 和 `aapt` 的非零退出码视为真正失败

这样可以避免：

- 明明已经导出成功
- 却被外层脚本误判为构建失败

## GitHub Actions 复用方式

仓库已提供一份基础工作流骨架：

- [android-export.yml](../.github/workflows/android-export.yml)

当前设计为：

- `workflow_dispatch` 手动触发
- 使用 `self-hosted + windows` runner
- 直接调用同一份 `scripts/build-android.ps1`

这样本地和 CI 走的是完全同一套逻辑，不会出现“本地打包一套、CI 打包另一套”的分叉。

建议在 Actions 中配置：

- Repository Variables
  - `GODOT_EXE`
  - `ANDROID_SDK_ROOT`
  - `JAVA_HOME`
- Repository Secrets
  - `ANDROID_DEBUG_KEYSTORE`
  - `ANDROID_DEBUG_KEYSTORE_PASSWORD`
  - `ANDROID_DEBUG_KEY_ALIAS`
  - `ANDROID_DEBUG_KEY_PASSWORD`
