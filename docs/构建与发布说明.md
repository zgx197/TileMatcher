# 构建与发布说明

## 目标

本文档用于统一说明当前仓库的本地构建、CI 发布、平台支持范围和验收约定。

当前原则是：

1. 本地与 GitHub Actions 复用同一套核心脚本入口。
2. Android 和 Windows 走真实可复用的导出链路，而不是临时手工流程。
3. Web 目标保留为显式限制说明，不伪装成已经可用。
4. 发布前尽量补齐自动化冒烟验证，降低“能出包但启动即退”的风险。

## 当前支持范围

### Android

- 已有 Godot 导出预设
- 已有本地脚本
- 已接入 GitHub Actions
- 当前可生成：
  - `TileMatcher-<version>-android-debug.apk`
  - `TileMatcher-<version>-android-debug.apk.sha256.txt`

### Windows Desktop

- 已有 Godot 导出预设
- 已有本地脚本
- 已接入 GitHub Actions
- 当前可生成：
  - `TileMatcher-<version>-windows-x64.zip`
  - `TileMatcher-<version>-windows-x64.zip.sha256.txt`

zip 内当前至少包含：

- `TileMatcher.exe`
- `TileMatcher.pck`
- `data_TileMatcher_windows_x86_64/`

### Web

当前项目是 Godot 4 C# / .NET 工程。

现阶段不把 Web 当成可正常出包的目标，原因是引擎限制而不是脚本缺失：

- Godot 4 的 C# 项目当前不能导出到 Web
- `scripts/build-web.ps1` 会直接报出这个阻塞点

官方文档：

- <https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html>

## Android 构建链路

### 环境前提

至少需要：

- `ANDROID_HOME` 或 `ANDROID_SDK_ROOT`
- `JAVA_HOME`
- `adb`
- `keytool`

同时需要：

- Godot 对应版本的 Android export templates
- Godot Editor Settings 中正确配置 SDK、JDK 与 `adb`

### 当前标准流程

`build-android.ps1` 当前按以下顺序执行：

1. 同步 `project.godot`、`export_presets.cfg`、Android manifest 中的构建元数据。
2. 自动补齐 Android 导出所需的主题资源、启动背景资源和项目名称资源。
3. 自动从 Godot 的 `android_source.zip` 中提取模板 AAR，避免依赖本地残留的 `libs/*.aar`。
4. 调用 Godot `--headless --export-debug` 进行正式导出。
5. 在 Godot 没有正常退出但 APK 已稳定生成时，继续复用新鲜产物，而不是无限等待。
6. 使用 `apksigner` 完成签名。
7. 使用 `apksigner verify` 和 `aapt dump badging` 做最终校验。

### 产物与验收

默认输出目录：

- `godot/build/android/`

常见产物：

- `TileMatcher-unsigned.apk`
- `TileMatcher-<version>-android-debug.apk`
- `TileMatcher-<version>-android-debug.apk.sha256.txt`

建议首轮真机重点验证：

- 启动页到主页流转是否正常
- 竖屏 UI 是否完整适配
- 主页到游戏页切换是否正常
- 拖拽牌块时触摸输入是否稳定
- 通关后结算页与每日奖励页是否正常
- 重新启动应用后进度存档是否正确恢复

## Windows 构建链路

### 当前标准流程

`build-windows.ps1` 当前负责：

1. 调用 Godot Windows Desktop 导出预设生成运行时文件。
2. 等待 `.exe`、`.pck` 和 `data_TileMatcher_windows_x86_64/` 稳定落盘。
3. 组装发布目录并压缩为 zip。
4. 生成 `sha256` 校验文件。

### 当前验收重点

建议每次正式发布前至少确认：

- zip 可正常解压
- `TileMatcher.exe` 可以启动
- 导出目录内能按预期产生 `logs/`
- 关键页面流转正常

## GitHub Actions 发布链路

当前工作流拆为三层：

1. `metadata`
   - 解析版本号、tag 与启用的平台
2. `export-targets`
   - 以矩阵方式分别构建 Android / Windows
3. `release`
   - 下载矩阵产物并统一上传到同一个 GitHub Release

### 当前行为

- `push tag` 时：
  - 默认同时构建 Android 和 Windows
  - 最后统一聚合到同一个 GitHub Release
- `workflow_dispatch` 时：
  - 可分别控制 `build_android`
  - 可分别控制 `build_windows`
  - `publish_release=true` 时统一上传所选平台产物

### 当前发布原则

- hosted-runner 与本地共享核心脚本入口
- Android 与 Windows release 统一聚合
- `publish_release=false` 用于冒烟验证
- `publish_release=true` 用于正式发布

## 冒烟验证与提前校验

### Android

当前发布链路已经补到“构建后再做启动冒烟”的方向，重点是拦住：

- 安装能装但启动即退
- 导出成功但运行资源不完整

### Windows

当前发布链路同样需要在 zip 产物基础上补做：

- 解压
- 启动
- 基础运行日志校验

### workflow_dispatch 建议组合

- 双平台冒烟：
  - `build_android=true`
  - `build_windows=true`
  - `publish_release=false`
  - `prerelease=true`
- 只做 Windows 冒烟：
  - `build_android=false`
  - `build_windows=true`
  - `publish_release=false`
  - `prerelease=true`
- 只做 Android 冒烟：
  - `build_android=true`
  - `build_windows=false`
  - `publish_release=false`
  - `prerelease=true`

### gh CLI 触发示例

```powershell
gh workflow run ".github/workflows/android-export.yml" `
  -f build_android=true `
  -f build_windows=true `
  -f publish_release=false `
  -f prerelease=true
```

结果检查：

```powershell
gh run list --workflow ".github/workflows/android-export.yml" --limit 5
gh run view <run-id>
gh run view <run-id> --log-failed
```

## GitHub Secrets

Android 构建当前至少需要这四项：

- `ANDROID_DEBUG_KEYSTORE_BASE64`
- `ANDROID_DEBUG_KEYSTORE_PASSWORD`
- `ANDROID_DEBUG_KEY_ALIAS`
- `ANDROID_DEBUG_KEY_PASSWORD`

如果使用 Godot 默认调试 keystore，常见值为：

- keystore password: `android`
- key alias: `androiddebugkey`
- key password: `android`

## 已知限制

- Web 目标仍受 Godot 4 C# 导出限制阻塞
- 工作流文件名仍保留 `android-export.yml` 历史命名
- `artifacts/mahjong-mvp/` 等目录名仍沿用历史命名，不代表当前题材方向

## 故障排查入口

遇到构建或发布问题时，优先检查：

- 构建脚本日志
- GitHub Actions 失败 job 日志
- Android 签名与导出资源是否同步刷新
- Windows 导出目录是否生成运行时依赖和 `logs/`

运行时启动问题可继续参考：

- [运行时日志系统设计](./运行时日志系统设计.md)
