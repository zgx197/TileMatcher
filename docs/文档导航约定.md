# 文档导航约定

## 目标

本约定用于明确 `docs/` 目录中哪些文档是当前有效设计，哪些文档只是历史归档，避免后续协作时误把旧方案继续当作主方案使用。

## 目录分层

- `docs/` 根目录只放当前仍然有效、仍然会继续维护的文档。
- `docs/归档/` 只放历史方案、废弃方案、阶段性原型记录。
- 任何不再作为实现依据的旧设计，都必须移入 `docs/归档/`，不应继续留在 `docs/` 根目录。

## 文档状态定义

文档默认分为两类：

- 当前文档
  - 表示当前阶段仍然有效
  - 可以继续修改
  - 可以直接作为实现、重构、讨论和评审依据
- 归档文档
  - 表示只用于追踪历史背景
  - 不应继续作为当前实现依据
  - 如需引用，必须明确说明“仅作历史参考”

## 使用规则

- 新开一个实现话题前，优先阅读 `docs/README.md` 中“当前文档”部分。
- 如果某份文档在 `docs/归档/` 中，默认不能直接拿来指导当前实现。
- 如果当前方案替代了旧方案，旧方案文档必须补充“已归档 / 被谁替代”的说明。
- 如果新方案已经成为主方案，必须在 `README.md`、`AGENTS.md`、`docs/README.md` 中同步更新入口。

## 命名规则

- 当前主设计文档，文件名应直接体现其职责，例如“通用堆叠框架与第二代网格方案”。
- 归档文档文件名应显式带出历史属性，例如“第一代网格坐标系统设计”。
- 不再建议继续使用过于泛化、容易与新方案混淆的名字作为主入口，例如单独使用“网格坐标系统设计”。

## 迁移规则

当某份文档从当前文档转为历史文档时，按以下步骤处理：

1. 将文件移动到 `docs/归档/`。
2. 在归档文档开头说明它为什么被归档、被哪份文档替代。
3. 修正 `README.md`、`AGENTS.md`、`docs/README.md` 内的引用。
4. 检查其他设计文档中的交叉引用，避免仍然指向旧位置。

## 当前项目约定

截至当前阶段，本项目文档入口约定如下：

- 当前主方案：
  - `docs/通用堆叠框架与第二代网格方案.md`
- 当前表现分析：
  - `docs/截图画面与渲染方式分析.md`
- 当前文档导航入口：
  - `docs/README.md`
- 历史归档方案：
  - `docs/归档/第一代网格坐标系统设计.md`

## 维护要求

- 只要设计方向发生切换，就要同步更新本文件。
- 如果只是补充细节而没有改变主方案，不需要新增归档。
- 如果旧文档仍然有保留价值，应归档，而不是删除。
