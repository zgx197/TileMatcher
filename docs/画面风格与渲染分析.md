# 画面风格与渲染分析

## 目标

本文档用于记录对参考游戏截图的画面分析结论，明确当前项目第一版应采用 Godot 2D 还是 Godot 3D，并沉淀后续实现游戏页视觉时需要保留的关键特征。

本文档关注的是：

- 截图中体现出的渲染特征
- 这些特征更接近 2D 还是 3D
- 为什么当前项目应继续选择 Godot 2D
- 后续如何用 2D 做出接近目标图的 2.5D 层叠效果

## 结论

基于当前参考截图，结论如下：

- 该游戏画面大概率是以 2D 分层渲染为主
- 即便原始项目内部某些资源来自 3D 预渲染，其运行时效果也完全可以用 2D 方式复刻
- 当前项目第一版不需要 Godot 3D
- 应采用 Godot 2D 来实现游戏页，并通过 2D 资源、阴影和层级关系营造 2.5D 视觉效果

更准确的表述是：

- 这是一个“逻辑 3D、表现 2D”的牌桌
- 不是一个必须依赖真实 3D 场景、3D 摄像机和 3D 物理的项目

## 画面特征分析

## 1. 所有牌块朝向完全一致

截图中所有牌块都正面朝向玩家：

- 没有看到绕 X 轴的俯仰变化
- 没有看到绕 Y 轴的左右旋转
- 没有看到近大远小的透视缩放

这说明画面不是在强调真实三维相机视角，而是在强调规则清晰的平面堆叠关系。

这类表现更符合 2D 分层渲染。

## 2. 厚度表现是固定样式，不像实时 3D 光照

每张牌块都存在以下视觉特征：

- 白色牌面
- 右侧和底部的深色厚度边
- 固定方向的阴影
- 统一的边缘高光

这些表现的特点是非常稳定、风格统一，并没有明显受到实时光照、实时摄像机角度或材质反射影响。

这更像：

- 2D 精灵贴图
- 或者由 3D 烘焙出的静态贴图
- 再配合运行时的 2D 分层显示

它不像一个真正依赖 3D 场景实时计算光照和投影的系统。

## 3. 层叠关系本质是遮挡顺序，而不是立体透视

截图中高层牌块压在低层牌块上方，主要通过以下方式表达：

- 绘制顺序
- 固定方向阴影
- 牌与牌之间的覆盖关系

没有出现明显的透视畸变，也没有出现由于视角变化带来的空间缩放差异。

这说明该牌桌的视觉重点在“谁盖住谁”，而不是“真实世界中的 3D 空间”。

这恰好对应我们当前已经设计好的逻辑模型：

- 使用 `(gx, gy, gz)` 表示空间层级
- 使用投影重叠判断压住关系
- 使用 `z_index` 表示显示顺序

## 4. 被选中的牌块像 2D 高亮态，而不是 3D 抬起态

截图左侧被选中的牌块表现为：

- 外部黄色描边
- 内部浅绿色高亮
- 轻微抬起感

这种效果非常像 2D 中的：

- 选中描边层
- 发光层
- 位置轻微偏移
- 或者缩放、阴影增强

它不像典型的 3D 抓取表现，没有看到明显的翻转、俯仰或立体旋转。

## 5. 整体界面构图更像 2D 手机 UI

整个游戏页是典型的手机竖屏布局：

- 顶部状态信息
- 中间牌桌
- 底部道具按钮

背景、牌桌、HUD 和按钮都在统一的平面构图体系中，没有明显依赖 3D 镜头语言。

这说明整体产品体验是偏 UI 导向的，而不是偏场景导向的。

对这种产品来说，Godot 2D 更自然。

## 为什么不建议第一版使用 Godot 3D

如果项目第一版使用 Godot 3D，会额外引入很多当前不需要的复杂度。

### 1. 相机与投影复杂度上升

需要处理：

- 3D 摄像机选择
- 透视或正交投影
- 手机纵屏视野适配
- 牌桌构图与空间布局

这些内容对第一版“打通游戏页核心逻辑”没有直接帮助。

### 2. 拖拽交互更复杂

在 3D 中实现拖拽通常需要处理：

- 屏幕坐标转射线
- 射线拾取对象
- 与拖拽平面的空间换算

而在 2D 中，拖拽交互可以直接使用屏幕坐标和节点位置，明显更适合快速迭代。

### 3. 3D 渲染收益有限

当前参考图并没有展示明显依赖 3D 的视觉特征，例如：

- 强透视镜头
- 牌面真实翻转
- 动态镜头运动
- 实时光照变化

因此使用 3D 会增加成本，但不会显著提升第一版成果质量。

## 为什么 Godot 2D 足够复刻该画面

Godot 2D 已经可以完整支撑当前目标效果：

- 多层牌堆叠
- 牌与牌之间的覆盖关系
- 拖拽交互
- 选中高亮
- 吸附消除
- HUD 与底部按钮

需要的并不是 3D 空间，而是以下这些 2D 能力：

- `Node2D` 层级管理
- `z_index` 绘制排序
- 阴影贴图或阴影偏移
- 选中描边
- 少量 Tweens 动画
- 合理的材质或 shader 做发光、高亮

## 推荐技术路线

第一版游戏页建议采用以下方式实现：

- 牌桌主体使用 `Node2D`
- 单张牌块使用 `Node2D`
- 顶部和底部 HUD 使用 `Control`
- 层级关系通过 `z_index` 控制
- 厚度感通过 2D 贴图或组合节点模拟
- 阴影使用固定方向阴影，不做实时 3D 光照

## 牌面视觉拆解建议

单张牌块的视觉可以拆解为以下几个 2D 层。

### 1. 阴影层

位于牌底部，用于模拟牌块浮在背景上方的空间感。

特点：

- 固定方向
- 固定颜色
- 不依赖实时光源

### 2. 厚度层

位于牌的右侧和底侧，模拟牌块有一定厚度。

实现方式：

- 直接烘焙进牌底贴图
- 或拆成独立的 2D 深色边缘图层

### 3. 牌底层

白色圆角矩形，作为主承载面。

需要体现：

- 边缘柔和
- 微弱渐变或高光
- 和背景有足够分离度

### 4. 牌面图案层

承载具体牌面图案与主题元素。

第一版可先用占位文字或简化图标代替。

### 5. 高亮层

用于表示：

- 选中
- 可匹配
- 提示目标

可采用：

- 描边
- 外发光
- 半透明底色叠加

## 运行时视觉特征建议

为了让第一版更接近目标截图，建议保留以下几个运行时特征。

### 1. 选中牌抬起

当玩家选中或开始拖拽牌块时：

- 提高其 `z_index`
- 略微上移或放大
- 增强阴影和高亮

### 2. 固定方向阴影

每张牌都应带有统一方向的阴影，以形成稳定的空间层级感。

### 3. 层间遮挡清晰

高层牌必须稳定覆盖低层牌，不能出现排序闪烁或错误。

### 4. 不使用真实透视

第一版视觉上应保持平面清晰、规则清晰，不引入复杂视角。

## 对当前项目的正式建议

基于截图分析，项目当前阶段应采用以下正式方案：

- 使用 Godot 2D
- 不使用 `Node3D`、`Camera3D`、`MeshInstance3D`
- 游戏页主牌桌使用 2D 分层渲染
- 用 2D 资源和 2D 动画来表现立体感

如果后续需要更强的立体效果，也建议优先在 2D 框架内增强：

- 更精细的阴影
- 更好的牌面贴图
- 更强的高亮材质
- 更细腻的拖拽动画

而不是一开始切换到 3D 技术路线。
