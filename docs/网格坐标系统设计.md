# 网格坐标系统设计

## 目标

本文档定义 TileMatcher 第一版的通用网格坐标系统，用于支撑游戏页中的麻将堆叠、遮挡判定、可移动判定和后续拖拽匹配逻辑。

该方案需要满足以下目标：

- 支持任意层数堆叠，不对层数做硬编码限制
- 支持上层麻将位于下层四张麻将的结合点处
- 支持多层错位布局
- 使用整数逻辑坐标，避免浮点坐标带来的判定误差
- 将几何关系与玩法规则拆分，便于后续迭代

## 核心结论

采用统一的三维逻辑坐标系：

- 每张麻将由 `(gx, gy, gz)` 描述
- `gx`、`gy` 表示平面逻辑坐标
- `gz` 表示层级
- 每张麻将在逻辑平面上固定占用 `2 x 2` 单位

该设计的本质不是让牌变大，而是把“半格偏移”整数化。

## 为什么一张牌占 `2 x 2`

本游戏的关键布局特征是：

- 下层麻将规则排布
- 上层麻将位于下层四张麻将的交点附近

如果每张牌只占 `1 x 1`，那么上层位于四牌交点时，坐标天然落在 `0.5` 的位置，必须引入：

- 浮点坐标
- 每层固定偏移规则
- 或者特殊 case

这些方案都不利于构建可维护的通用系统。

将网格精度提升一倍后：

- 原来 `1 x 1` 的麻将，逻辑上变为 `2 x 2`
- 原来需要 `0.5` 表达的偏移，现在可用整数 `1` 表达

因此：

- `2 x 2` 不是视觉尺寸，而是逻辑尺寸
- 它的作用是让半格错位可以用整数坐标稳定表达

## 坐标定义

每张麻将使用左上角作为逻辑锚点。

建议数据结构：

```csharp
public sealed class TileData
{
    public int Id;
    public string Type = "";
    public int GX;
    public int GY;
    public int GZ;
    public bool Removed;
    public bool Movable;
}
```

字段说明：

- `GX`：逻辑平面左上角 X 坐标
- `GY`：逻辑平面左上角 Y 坐标
- `GZ`：层级，非负整数
- `Removed`：是否已消除
- `Movable`：当前是否可移动

说明：

- 坐标系统本身不要求 `GX`、`GY` 必须为正数
- 后续牌桌可通过扫描边界盒统一居中显示

## 空间模型

每张麻将在逻辑平面上的占用区域为：

- `left = GX`
- `top = GY`
- `right = GX + 2`
- `bottom = GY + 2`

也可以记为一个 `2 x 2` 的矩形投影。

例如：

- 一张牌在 `(0, 0, 0)`，占用 `[0, 2) x [0, 2)`
- 一张牌在 `(2, 0, 0)`，占用 `[2, 4) x [0, 2)`
- 一张牌在 `(1, 1, 1)`，占用 `[1, 3) x [1, 3)`

第三张牌正好位于前两层四张牌的交点偏移位置。

## 为什么该方案适合多层堆叠

所有层共享同一套平面坐标系，不存在“某一层使用特殊坐标定义”的情况。

因此：

- 第 1 层和第 10 层的计算方式完全相同
- 更高层可以直接与任意更低层做投影重叠判断
- 系统不会因为层数增加而引入新的特殊逻辑

这正是该方案能够支持无限层扩展的原因。

## 关卡布局约定与系统能力

需要区分两件事：

### 坐标系统能力

坐标系统允许：

- 任意层数
- 任意整数坐标
- 任意符合占位规则的堆叠关系

### 关卡布局约定

为了让第一版布局更清晰，关卡数据可以优先遵守以下约定：

- 常规底层牌放在偶数坐标，如 `(0,0)`、`(2,0)`、`(4,2)`
- 位于交点处的上层牌放在奇数坐标，如 `(1,1)`、`(3,1)`

这是推荐的关卡构造方式，不是底层坐标系统的硬限制。

这样处理的好处是：

- 第一版关卡更容易读
- 更容易观察上层压住下层的关系
- 后续如需做异形关卡，也不会被坐标系统卡死

## 统一几何规则

网格模块只负责几何关系，不直接负责玩法结论。

它至少要支持以下几类查询。

### 1. 获取麻将投影矩形

```csharp
Rect2I GetFootprint(TileData tile)
```

用于获得麻将在逻辑平面上的占位范围。

### 2. 判断两张麻将是否平面重叠

```csharp
bool OverlapsXY(TileData a, TileData b)
```

推荐实现：

```csharp
bool OverlapsXY(TileData a, TileData b)
{
    return a.GX < b.GX + 2 &&
           a.GX + 2 > b.GX &&
           a.GY < b.GY + 2 &&
           a.GY + 2 > b.GY;
}
```

该判断只看平面投影，不看层级。

### 3. 判断某张麻将上方是否有遮挡

```csharp
bool HasAnyAboveOverlap(TileData tile, IEnumerable<TileData> allTiles)
```

规则：

- 只要存在任意更高层麻将 `other.GZ > tile.GZ`
- 且其与当前牌平面投影重叠
- 就认为当前牌被上方遮挡

注意：

- 这里不能只检查 `GZ + 1`
- 任意更高层都应参与判断

这是无限层方案下必须坚持的原则。

### 4. 查询同层邻接关系

```csharp
IEnumerable<TileData> GetSameLayerNeighbors(TileData tile, IEnumerable<TileData> allTiles)
```

该接口用于后续实现：

- 左右阻挡判定
- 上下阻挡判定
- 可移动状态计算

文档当前只定义网格系统，不在这里写死“卡住”规则细节。

## 屏幕坐标换算

逻辑坐标与渲染坐标需要明确分离。

建议定义：

- `tileWidth`：麻将显示宽度
- `tileHeight`：麻将显示高度
- `stepX = tileWidth / 2`
- `stepY = tileHeight / 2`

坐标换算公式：

```csharp
Vector2 GridToWorld(int gx, int gy, Vector2 boardOrigin)
{
    float stepX = TileWidth * 0.5f;
    float stepY = TileHeight * 0.5f;
    return boardOrigin + new Vector2(gx * stepX, gy * stepY);
}
```

结果：

- `(2, 0)` 相对 `(0, 0)` 右移一整张牌宽
- `(1, 1)` 相对 `(0, 0)` 右下各偏移半张牌

这与目标游戏的多层错位布局一致。

## 层级渲染建议

逻辑层级 `gz` 与渲染排序不是一回事，但两者必须稳定关联。

第一版建议使用如下排序规则：

```csharp
zIndex = GZ * 10000 + GY * 100 + GX;
```

作用：

- 高层一定画在低层之上
- 同层中更靠下的牌优先显示在前
- 使用 `GX` 打破同层平局

该规则足够支撑第一版占位渲染，后续可根据视觉需求微调。

## 模块职责边界

网格系统模块负责：

- 定义逻辑坐标
- 定义麻将占位尺寸 `2 x 2`
- 提供 `GridToWorld`
- 提供投影重叠判断
- 提供同层邻接查询基础接口
- 提供边界盒计算能力

网格系统模块不负责：

- 拖拽输入
- 匹配消除
- 分数
- 胜负
- HUD
- 页面切换

这样可以避免后续规则和显示逻辑耦合。

## 推荐类划分

第一版建议至少准备以下类。

### `GridConfig`

负责定义：

- 麻将显示宽高
- 逻辑步长
- 牌桌原点
- 可能的层间视觉偏移参数

### `GridPosition`

轻量坐标结构：

```csharp
public readonly struct GridPosition
{
    public readonly int X;
    public readonly int Y;
    public readonly int Z;
}
```

### `TileData`

负责存储单张麻将的逻辑信息。

### `GridMath`

静态工具类，负责：

- `GridToWorld`
- `GetFootprint`
- `OverlapsXY`
- 后续扩展的方向阻挡辅助查询

### `LevelLayout`

负责保存关卡中全部麻将的布局数据。

## 第一版实现约束

为了尽快推进编码，第一版建议遵守以下约束：

- 先做固定单关
- 先做静态布局数据
- 先实现正确的显示、投影和层级
- 不在网格模块里引入拖拽物理
- 不在网格模块里实现胜负和消除

也就是说，第一步的目标是让牌桌“站住”，而不是立即让牌桌“能玩”。

## 验收标准

网格模块完成后，应满足以下最小验收条件：

- 可以用逻辑坐标生成多层麻将布局
- 同层牌能按统一步长稳定排布
- 上层牌可以通过奇数坐标落在下层四牌结合点处
- 任意两张牌的投影重叠关系可稳定计算
- 牌桌可通过逻辑边界盒完成居中显示
- 不依赖输入系统，也能正确渲染静态堆叠结构

## 当前结论

在当前项目阶段，网格系统采用以下正式定义：

- 使用统一整数逻辑坐标系
- 每张麻将固定占用 `2 x 2` 逻辑单位
- 每张麻将由 `(gx, gy, gz)` 表示
- `gz` 不设硬编码上限
- 所有层共享同一平面坐标系
- 上层压住下层通过平面投影重叠自然导出
- 关卡推荐使用偶数层/奇数层错位布局，但这不是系统硬限制

该文档作为后续 `GridConfig`、`GridMath`、`TileData` 和 `LevelLayout` 的实现依据。
