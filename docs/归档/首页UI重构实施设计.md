## 1. 文档目标

本文用于整理“毛球碰碰乐”首页的重构方案，并明确 MVP 分阶段落地方式。

本次重构不追求一次做完完整宠物经营系统，而是先完成以下两件事：

- 把首页的信息结构从“旧启动页样式”重构成“宠物救助 + 宠物乐园 + 益智赚金币”的产品首页
- 提前建立可持续演进的 UI 分层规则，避免后续弹窗、调试面板、活动面板继续互相遮挡

## 2. 重构背景

当前首页更像一个简化版启动页，核心问题有：

- 主视觉仍然偏“标题页”，没有体现宠物救助与宠物乐园的产品定位
- 中部区域没有承载“已领养宠物”的展示职责
- 首页缺少“宠物救助入口”的显式按钮
- 关卡入口虽然存在，但没有和“赚取金币”形成明确叙事
- 首页弹窗与调试面板未来若继续直接混在普通内容层，容易再次出现层级遮挡和交互打架

因此，首页需要从“单纯进关卡”升级成“玩家资产首页”。

## 3. 新首页信息结构

首页拆分为三个主区域。

### 3.1 顶部资源与入口区

职责：

- 提供宠物救助入口
- 显示当前金币数量
- 保留 DEBUG 调试入口

建议结构：

- 左侧：`宠物救助`按钮
- 中间：品牌标题、欢迎语、金币数量
- 右侧：`DEBUG`按钮

### 3.2 中部宠物乐园区

职责：

- 作为首页主视觉区域
- 展示已领养宠物的生活状态
- 承担后续“宠物状态机”和“状态气泡”的可视化容器

MVP 阶段没有美术资源时，可采用：

- 不同颜色的圆角方块表示不同宠物
- 方块上的文字表示宠物名称
- 独立气泡文字表示当前生活状态

后续真实数据接入后：

- 已领养宠物进入乐园区生活
- 宠物状态机驱动状态切换
- 状态变化时短暂显示气泡文案

### 3.3 底部益智入口区

职责：

- 明确告知玩家“进入关卡是为了赚取金币”
- 展示当前要进入的关卡信息
- 保持主页到游戏页的核心主路径清晰直接

建议结构：

- 区块标题：`益智赚金币`
- 当前关卡标题
- 当前关卡说明
- 大按钮：`进入第 X 关`

## 4. MVP 分阶段实现

### 4.1 第一阶段

目标：

- 完成首页三段式布局
- 新增宠物救助弹窗
- 预留宠物乐园展示区
- 让首页弹窗和调试面板进入独立高层 UI 容器

本阶段不接入真实领养逻辑，只完成：

- 首页新结构
- 宠物救助列表静态展示
- 宠物乐园占位与视觉预演
- Debug 面板迁移到高层模态层

### 4.2 第二阶段

目标：

- 接入宠物定义数据
- 接入金币校验与扣费
- 接入已领养宠物存档
- 宠物救助列表支持真正领养

### 4.3 第三阶段

目标：

- 中部乐园区消费已领养宠物数据
- 不同宠物显示不同色块与名字
- 增加简单生活状态机
- 状态变化时显示气泡文案

### 4.4 第四阶段

目标：

- 宠物布局更自然
- 加入轻量移动、停留、发呆等表现
- 为后续宠物店、宠物互动、首页经营感扩展留出空间

## 5. 职责边界

### 5.1 AppRoot

负责：

- 持有玩家长期存档数据
- 读取金币数量、当前关卡、已领养宠物
- 响应首页发出的“进入关卡”“领养宠物”等请求
- 执行扣费、保存存档、重新刷新首页

不负责：

- 直接拼装首页上的具体控件细节

### 5.2 HomePage

负责：

- 展示首页三段式 UI
- 打开和关闭首页弹窗
- 展示当前金币、当前关卡、宠物乐园区域
- 向外发出“开始游戏”“打开调试”“领养请求”等 UI 信号

不负责：

- 直接修改玩家存档
- 直接完成金币扣费逻辑

### 5.3 宠物乐园视图

后续拆分为独立组件时负责：

- 根据已领养宠物数据渲染宠物块
- 驱动宠物生活状态的显示
- 控制气泡出现与消失

### 5.4 宠物救助弹窗

负责：

- 展示可领养宠物列表
- 展示描述、价格、状态
- 向外发送领养动作请求

## 6. 模态层与高层 UI 规则

这是本次重构必须记录并开始执行的规则。

### 6.1 规则

首页弹窗和 debug 面板以后都建议挂到独立高层 UI 容器里，最好是统一的遮罩层或模态层，不要继续直接混在普通首页内容层里。

### 6.2 原因

- 避免普通内容文字、按钮、卡片遮住弹窗
- 避免多个弹窗各自找层级补丁，越来越难维护
- 避免首页和游戏页重复踩 UI 层级问题
- 为后续宠物救助、活动弹窗、奖励弹窗、设置弹窗提供统一承载层

### 6.3 本次落地方式

首页第一阶段直接引入独立高层 UI 容器：

- 普通内容层：首页静态内容和主按钮
- 模态层：宠物救助弹窗、共享 Debug 面板

后续可以继续统一为：

- `ContentLayer`
- `ModalLayer`
- `ToastLayer`

## 7. 第一阶段可见结果定义

首页第一阶段完成后，应该满足以下可见结果：

- 首页顶部能看到宠物救助入口、金币和 DEBUG
- 首页中部有明确的宠物乐园区域
- 首页底部以“益智赚金币”作为进入关卡的主叙事
- 点击宠物救助按钮会弹出救助列表
- Debug 面板仍可正常打开
- 宠物救助弹窗和 Debug 面板不会被普通首页内容盖住

## 8. 后续衔接建议

在第一阶段稳定后，推荐按以下顺序继续推进：

1. 接入宠物定义数据与首页静态列表
2. 接入领养扣费和存档
3. 接入已领养宠物在乐园区展示
4. 为单只宠物补状态机与气泡
5. 根据宠物数量再决定是否做简单随机移动和自动布局
