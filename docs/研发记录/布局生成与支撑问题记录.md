# 布局生成与支撑问题记录

## 背景

在项目进入“可见、可测”的游戏页阶段后，布局生成与层级堆叠成为最频繁暴露问题的部分。

这条问题线贯穿了：

- 同层摆放
- 层间偏移
- 支撑判断
- 固定原型
- 随机生成

## 目标

目标并不是一次性做出最终关卡生成器，而是逐步建立：

- 同层稳定对齐
- 上层合法叠放
- 可用的固定原型
- 可调试的随机布局

## 问题 1：同层麻将挤在一起

### 现象

早期第二代网格接入后，曾出现同层麻将视觉上挤成一团的现象。

### 原因

根因是把：

- 逻辑微单元尺寸

和：

- 同层真实落点步长

混在了一起。

结果同层牌按过小步长在放置，导致同层 footprint 重叠。

### 解决方案

- 将同层默认步长改回与牌形一致
- 生成器中增加“同层互不重叠”的候选选择
- 校验器增加“同层重叠”检查

### 当前结论

当前项目把“同层绝不重叠”视为硬约束。

## 问题 2：上层压住效果不对

### 现象

曾出现两层堆叠观感不正确的情况，看起来不像“压两张”或“压四张”。

### 原因

真正需要调整的不是底层通用框架，而是：

- 上层相对下层的落点偏移配置

### 解决方案

把层间落点偏移正式抽成配置项：

- `None`
- `HalfX`
- `HalfY`
- `HalfXY`

并由：

- `LayerOffsetMode`
- `LayoutRules.UpperLayerOffsetMode`

统一驱动固定原型和随机生成器。

### 当前结论

当前支撑观感主要通过偏移模式调节，而不是重新修改底层几何规则。

## 问题 3：高层牌下方没有对应下层支撑

### 现象

曾出现：

- `L2` 的牌下面并没有 `L1` 对应支撑
- 高层看起来像悬空

### 原因

固定原型最初是按“单层绝对偏移”在写坐标，而不是逐层累计偏移。

### 解决方案

固定原型改成：

- 逐层累计偏移

也就是说：

- `L1` 基于 `L0`
- `L2` 基于 `L1`
- `L3` 基于 `L2`

### 当前结论

当前固定原型必须和当前规则一起演化，不能保留一套脱离规则的硬编码坐标。

## 问题 4：上层完全盖住下一层一张牌

### 现象

曾出现：

- 一张上层牌和下一层某张牌完全同 footprint 重合

这会导致下层牌被完全盖住，不符合当前目标玩法。

### 原因

这通常来自：

- 层间偏移计算不正确
- 原型坐标写法错误

### 解决方案

校验器新增相邻层完全重合检查：

- 如果 `GX / GY / 宽 / 高` 全部一致，直接判定非法布局

### 当前结论

当前项目明确把“相邻层完全重合”视为非法。

## 问题 5：支撑概念和底层几何概念混淆

### 现象

在设计讨论中，容易把：

- 被两张牌支撑
- 被四张牌支撑

直接写成底层规则。

### 原因

这是从第一代方案惯性延续下来的思路。

### 解决方案

明确统一：

- 支撑是结果层术语
- 完整底面覆盖是底层规则

### 当前结论

当前底层通用框架不直接编码“二支撑 / 四支撑”。

## 当前结论

布局与支撑相关的当前稳定约束包括：

- 同层绝不重叠
- 上层不能与下一层完全重合
- 上层必须获得完整底面覆盖
- 偏移模式负责决定支撑观感
- 固定原型必须随当前规则同步演化

## 后续待验证

后续仍需继续验证：

- 是否需要更多偏移模式
- 是否要在调试 UI 中直接显示“被几张下层牌覆盖”
- 随机布局是否需要进一步加入支撑形态偏好
