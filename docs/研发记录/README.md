# 研发记录目录

## 目录目标

本目录用于记录项目开发过程中真实发生过的问题线、方案演进、定位过程和解决方案。

这些文档不是“当前最终设计”的替代品，而是补充说明：

- 为什么项目会演进到当前这套实现
- 中间踩过哪些坑
- 哪些问题已经被定位并解决
- 哪些问题未来可能再次出现

## 与其他文档的分工

- `docs/堆叠框架与网格规则设计.md`
  - 记录当前采用的主设计方案
- `docs/代码架构与配置说明.md`
  - 记录当前代码和配置结构
- `docs/研发记录/*.md`
  - 记录研发过程中的问题线、方案演进和排查经验

一句话区分：

- 主设计文档回答“现在采用什么”
- 研发记录回答“为什么变成这样”

## 建议记录规则

新增研发记录时，建议按“问题线”聚合，而不是按日期写流水账。

每篇记录至少包含：

- 背景
- 目标
- 问题现象
- 原因分析
- 解决方案
- 当前结论
- 后续待验证

## 什么时候必须更新研发记录

满足以下任意一条时，应同步更新本目录中的对应文档：

- 设计方向发生改变
- 花了明显时间定位出一个真实问题
- 修掉了一个未来很可能再次出现的坑
- 新增了一条重要工程约束或调试经验
