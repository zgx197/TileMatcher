# 网格系统演进记录

## 背景

项目最初目标是快速复刻类似 Vita Mahjong 的堆叠配对玩法，因此第一阶段优先采用了更简单的整数坐标方案。

早期原型的重点是：

- 尽快把多层堆叠效果做出来
- 尽快看到“上层压住下层”的基础视觉
- 尽快验证层级和可视化调试是否可行

## 初始方案

第一代方案的核心特征是：

- 每张牌固定占用 `2 x 2` 逻辑单位
- 上层牌通过半格错位落在下层四牌交点附近
- “四点支撑”几乎被网格结构天然写死

这套方案的优点是：

- 简单
- 稳定
- 很适合快速原型

但很快也暴露出明显问题：

- 无法表达更接近目标画面的长方形牌
- 很难自然出现“被两张牌支撑”与“被四张牌支撑”的差异
- 支撑逻辑被坐标系统硬编码，扩展性差

## 方案转折点

在后续讨论中，核心认知发生了改变：

- “支撑模式”不应该是底层规则
- “完整底面覆盖”才应该是底层规则

也就是说：

- 两支撑不是底层输入
- 四支撑也不是底层输入
- 它们应该是几何覆盖结果

这直接推动项目从第一代方案转向第二代通用堆叠框架。

## 第二代方案

第二代方案的核心变化是：

- 基础逻辑空间仍使用整数网格
- 每张牌不再默认等于一个固定位置单元
- 每张牌由一个矩形 footprint 描述
- 当前标准牌块 footprint 设定为 `4 x 6`
- 上层合法性通过“底面完整覆盖”判断

这套方案的关键价值在于：

- 更接近目标画面的长宽比例
- 能自然表达不同支撑结果
- 更适合作为后续通用堆叠框架基础

## 关键代码落地

这次演进最终落到以下核心代码：

- `godot/scripts/data/TileShape.cs`
- `godot/scripts/data/TileData.cs`
- `godot/scripts/grid/GridConfig.cs`
- `godot/scripts/grid/GridMath.cs`
- `godot/scripts/layout/LayoutRules.cs`
- `godot/scripts/layout/RandomStackLayoutGenerator.cs`
- `godot/scripts/layout/LayoutValidator.cs`

## 当前结论

当前项目已经明确采用第二代方向：

- 默认牌形为 `4 x 6`
- 核心几何规则是完整底面覆盖
- 第一代 `2 x 2` 方案只作为归档背景保留

## 后续待验证

后续仍需继续验证：

- `4 x 6` 是否是最终最优标准尺寸
- 是否需要支持更多矩形牌形
- 是否需要把偏移模式扩展成更通用的层序列表达
